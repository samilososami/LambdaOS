Connection & safety

This page is static. Chrome speaks ADB to the phone directly over WebUSB — there is no local server API and no bridge. Web Serial cannot carry ADB: the phone exposes a vendor-specific USB interface (0xff / 0x42 / 0x01), not a serial port.

Before connecting, stop the computer’s adb server, because it owns the USB interface:

adb kill-server

Then plug the S10 in, press Connect over USB and pick it in Chrome’s device chooser. On Linux, allow vendor 04e8 for your user with a udev rule (TAG+="uaccess"). On Windows the ADB interface must be bound to WinUSB (Zadig); the Samsung driver blocks WebUSB.

The first link shows Android’s “Allow USB debugging?” prompt, then LEX’s own consent prompt with this device’s name. “Permitir siempre” remembers that name; connect_forget removes it.

Start and Stop are typed system.desktop jobs in Lambda Core, never free-form shell. WebUSB cannot open host TCP ports, so the embedded noVNC view is gone: to watch the desktop, run adb forward tcp:6080 tcp:6080 on a computer and open http://127.0.0.1:6080/vnc.html. The VNC password is never displayed or logged here.
