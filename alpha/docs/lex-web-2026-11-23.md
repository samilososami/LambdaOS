# LEX web dashboard over ADB — 2026-11-23

Status: implemented and device-tested with the `0.2.0-operator.25/26` line.
The dashboard lives in `alpha/web/lex-dashboard` and is a zero-dependency Node
server on `127.0.0.1:7788`; it talks to the S10 through adb and the typed Core
RPC. The live Start/Stop/iframe test ran on .25; .26 keeps the same API and
was verified for status/jobs/desktop state.

## What it does

- Device pill and metrics: model, Android release, worker online, battery
  level/status/temperature, Wi-Fi SSID/IP, `/data` free space, Core version.
- Desktop card: embeds the noVNC session in a 19:9 frame; when stopped it shows
  a designed empty state; when Core says the desktop runs but the adb forward
  is missing it offers **Restore connection**.
- Start/Stop submit the typed `system.desktop` job, poll it, then create or
  remove `adb forward tcp:6080` and `tcp:5901`. No free-form adb or shell.
- Recent Core jobs with state chips, duration and error; ADB screenshot preview.
- Dark LambdaOS palette, dotted-gradient backdrop, no external assets or CDNs.

Run:

```sh
cd alpha/web/lex-dashboard
node server.mjs            # http://127.0.0.1:7788
```

Requirements: Node 18+, `adb` in PATH and the S10 authorized; the LEX rootfs
and scripts installed. See `alpha/web/lex-dashboard/README.md` for the API and
security posture.

## Verification (S10, 2026-11-23)

- The server self-check and `node --check` passed; the page loaded with the S10
  pill and live metrics (battery 100%, Wi-Fi 2.4GHz_TEST, 72.7 GB free, Core
  0.2.0-operator.26, worker online).
- **Restore connection** set both forwards and the iframe showed the Kali XFCE
  desktop (panel, icons, LambdaOS wallpaper).
- **Stop** completed the typed stop job (~15–19 s), removed both forwards,
  returned the notification to “Listo · Wi-Fi, Bluetooth y USB” and showed the
  “Desktop is off” state.
- **Start** completed the typed start job, recreated the forwards and displayed
  the live desktop in the iframe; the Core notification showed “LEX · escritorio”.
- Jobs table and screenshot card rendered real data; the dashboard followed the
  desktop state while another process was toggling it.
- With `0.2.0-operator.26`, the API was retested directly: `/api/device`
  reported Core .26; `POST /api/desktop/start` returned running, geometry and
  ports and created both forwards; `POST /api/desktop/stop` removed them and
  returned running false.
- The server was stopped after validation; start it with
  `node alpha/web/lex-dashboard/server.mjs` when needed.

## Known limits

- Local-only, no authentication by design. Never bind or reverse-proxy it to a
  LAN interface; the VNC password is returned to the local page to build the
  noVNC URL and must not be logged.
- Start/Stop take about 15–19 s because the chroot scripts are synchronous
  (vncserver/Perl startup, websockify port waits). The dashboard uses a 30 s
  timeout; an optimization is listed in IDEAS.
- Only the pinned/only attached device is targeted; wireless adb and
  multi-device selection are not implemented.
- One early noVNC “Failed to connect” was Xvnc blacklisting 127.0.0.1 after
  failed authentication attempts from a stale page; restarting the desktop
  cleared it and a fresh page connected. The server and forward were fine.
