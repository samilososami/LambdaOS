# Security model

LambdaOS security workflows are built around a closed operation catalogue rather
than a general-purpose privileged shell.

## Principles

1. **Typed inputs.** Operation names, targets and arguments are validated before
   reaching a privileged worker.
2. **Fresh observations.** Target identity and capability must come from current
   device state, not untrusted UI text or model output.
3. **Explicit scope.** Active operations require authorization tied to the
   concrete operation and target.
4. **Bounded execution.** Time, retries, output, memory and process lifetime are
   limited. Child processes receive parent-death handling where supported.
5. **Structured results.** Success, no result, timeout, unavailable capability,
   partial result and failure remain distinct.
6. **Independent verification.** A recovered candidate is checked separately
   before persistence or connection.
7. **Receipts.** Core records what was requested and what was actually observed.
8. **System integrity.** SELinux remains enforcing; EFS, modem, bootloader and
   firmware partitions are outside ordinary Operator workflows.

## AI boundary

Lamb may choose among declared operations and interpret structured results. It
does not receive arbitrary root execution. A model statement such as “completed”
cannot replace executor evidence, and a model-provided confirmation field cannot
authorize an operation.

## Publication boundary

Private keys, ADB credentials, raw captures, recovered credentials, SSIDs/device
identifiers, backups, model weights and private test logs are excluded from this
repository. Synthetic fixtures may be regenerated by the reviewed scripts.
